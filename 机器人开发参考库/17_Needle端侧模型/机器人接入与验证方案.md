# 机器人接入、失败分析与验证方案

本文件是后续实施方案；当前资料库完成下载、静态核查、SDK检查和离线推理，没有部署机器人网关。

## 第一版如何分层

推荐“输入/ASR→Needle或规则解析→应用验证器→动作适配→设备执行→回执”。纸壳第一版仍使用明确按钮、规则和预设动作；Tiny提供表现层范例，Needle提供意图解析实验范例，ESP32-C3只负责自己的显示、输入和经过校准的舵机。

模型仅允许看到有限工具，例如`show_expression(expression)`、`nod(count)`和`get_device_status()`。接口不要暴露任意Python、shell命令、GPIO写入或原始PWM。这里是建议的工具合同，不能视为现有纸壳V0.3协议。

## 两轮对照与正式十个样例的发现

环境为固定SDK3.1.0、Needle3固定HF权重、macOS x86_64 wheel、遥测关闭、显式本地文件；每次reset，关闭auto_date，system使用`locale: en-US; device: desktop-robot`事实，只声明表情与点头schema，无真实函数绑定，只调用complete。

| 输入 | 观察结果 | 对执行层的要求 |
|---|---|---|
| Show a happy face. | 有效show_expression(happy)，置信度0.8885 | 仍须核对设备和表情白名单 |
| Nod twice. | nod(count=2)在suppressed_calls，function_calls为空 | 不执行被抑制的建议 |
| Nod 2 times. | 有效nod(count=2)，置信度0.9183 | 说明措辞影响，需覆盖数字和数量词 |
| Tell me the capital of France. | 空调用，未产生动作 | 无关问题保持静止 |
| Do not nod.，128与512 token | validation.negation=true，调用被抑制；无有效调用 | 不从被否定或被抑制的建议执行 |
| 请显示开心的表情。，128与512 token | success=true，误解为翻译任务，空调用 | 中文任务失败，不以success作为任务完成 |
| 点头两次。，128与512 token | 错误表情建议被抑制；有效调用为空 | 不应自动执行低置信度错误建议 |

表格合并预算复测后正式一轮共10次推理。另保留初次指令式system对照轮10次；该轮部分结果发生截断。改为上游llms.txt推荐的环境事实后，否定的处理改为抑制，中文两个样例仍失败。不要将提示不符合接口建议的结果混成统一准确率，也不能因此推出“所有中文都不支持”。[正式结果](<分析证据/离线指令试验.json>)与[初次对照](<分析证据/离线指令试验_指令提示对照.json>)保留完整返回。

推理调用无需联网不代表语音、前端、自动下载或所有遥测自动离线。本次用显式weights、NEEDLE3_LIB_PATH、HF_HUB_OFFLINE及遥测禁用变量固定路径，没有麦克风、学生数据、云微调或真实执行器。

## 动作网关应检查什么

1. 检查success/error、实际function_calls和suppressed_calls；没有有效调用或发生错误直接拒绝。
2. 校验函数名白名单、schema、参数类型与范围、未知字段和调用数量；计数、时长和幅度不得突破设备限值。
3. 判断置信度与语义，使用课程自己的测试集确定门槛；confidence=None不能当1，模型高置信度也不是授权。
4. 校验会话、设备绑定、教师/学生权限、任务ID、期限和频率。重复消息按ID去重，超时指令不重放。
5. 动作适配器输出设备协议，控制器再次限幅、限速，回传接受/拒绝/完成状态；断线和停止优先于动画。

这是我们建议新增的验证层，未包含在SDK strict的完整保障内。模型推理出错时反馈“未识别到可执行动作”，并提供明确按钮或教师确认；不从reasoning中自行补造参数。

## 与Tiny和纸壳的接口差异

Tiny现有HTTP只接受已注册的动画名。`nod(count=2)`并不能原样POST成为一个新动作；可以先将任务状态映射为现有动画，或在独立开发仓实现nod并补齐固件回执。纸壳V0.3网页工具的协议来自本库逆向证据，完整固件源码仍缺，首版不把新协议当现成能力。

校准范围来自实际纸壳机构，不能使用Tiny头/颈范围。Tiny abort存在动画保持时间，OE默认未接；纸壳网页关闭也未保证急停。自研停止与断线机制应在模型接入之前验证。

## 多学生平台与评测设计

原生头已说明进程全局非线程安全；当前默认模型路径共享状态，自定义weights worker独立进程。建议每设备会话隔离worker或按设备严格排队，独立命令reset；嵌入worker ABI差异先解决，再考虑语义检索。

建立固定测试集，至少覆盖：正确指令、数量词/数字、缺参数、范围错误、无关问句、否定、停止、连续/重复指令、中文/粤语文本、混合语言、误转录、设备不存在和断线。先做离线dry-run，再用假设备模拟消息和回执，最后接真实双轴纸壳。

指标分开记录“意图选对”“参数正确”“不该执行时拒绝”“设备执行成功”“端到端延迟”。关键否定/停止失败不可被总体高通过率掩盖；置信度阈值通过保留测试集校准，不能套一个宣传数字。

## 开工前明确缺口

- 补齐纸壳源代码/许可或建立自研控制器基线。
- 确认目标机器资源和SDK/引擎ABI，解决worker.embed参数不一致；当前未做ESP32移植。
- 对中文/粤语独立验证ASR与文本解析，不使用Whistle当前语言清单以外能力作承诺。
- 核验默认遥测、离线启动、并发隔离与模型版本升级。
- 准备真实动作、供电、限位和故障验收，后续结果另存，不与本次纯主机证据混写。

本次工具schema描述为英文，正式轮locale为en-US；两个中文样例不构成中文课程性能评测。后续需以zh-HK/zh-CN环境事实、实际课堂措辞和双语工具描述建立独立保留测试集，比较提示、训练或替换解析器的效果。
