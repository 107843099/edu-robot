# Needle：机器人与学生平台的端侧意图解析参考

**研发判断：适合放在电脑、手机或资源足够的边缘设备上，研究“自然语言→有限工具调用”；当前不作为ESP32-C3纸壳第一版的直接固件方案。** Needle是模型与SDK，不是实体机器人。它的价值在于意图选择、结构化参数和本地运行；实际动作仍由独立控制器完成。

主仓固定提交 `8881c1ceada54814465fa5edddc6599f32383985`，SDK版本3.1.0；核查日期2026-10-03。已下载主仓及同组织4个相关仓，共5份固定快照、828个文件；另保存固定Hugging Face版本的Needle3推理权重、当前引擎和Whistle资源，共76个文件、107,472,559字节。训练检查点与旧版引擎未下载，理由及路径全部记录。

## 为什么不直接放进纸壳C3

当前已发布17种原生/浏览器平台资源及8种3.1.0 Python引擎wheel；未找到ESP32/Xtensa或RV32裸机目标。Linux RISC-V64资源不等于ESP32-C3的RISC-V32固件。Flash容量、运行RAM、线程、文件系统和ABI都要匹配，不能仅因为简介写“microcontrollers”就认为现有纸壳板可部署。

可先在电脑端运行模型，输出预设表情或有限动作意图，再经校验适配Tiny的HTTP或自研纸壳协议。这是建议架构，不是本库已经完成的真机集成。

## 本地验证得到的真实限制

在按上游推荐设置环境事实的正式一轮中，英文`Show a happy face.`返回有效表情调用；`Nod 2 times.`返回count=2；但`Nod twice.`的调用进入suppressed_calls。无关问题和中文“请显示开心的表情。”没有动作；`Do not nod.`被标记否定并抑制。中文“点头两次。”误解为不相关表达并产生被抑制的表情建议。三个问题样例提高到512 token后结果未改善。初次采用指令式system的对照轮曾出现截断，说明提示方式会影响结果；完整保留，没有混入正式样例统计。

每轮10个样例、两轮20次只是离线冒烟试验，不是准确率评测。它们足以说明：不能只检查`type=call`或`success=true`就驱动硬件；必须读取实际function_calls、抑制项、错误、置信度和参数。失败或无有效调用时保持静止并给出可理解反馈。

SDK首轮选择的检查为91通过、1跳过、5因缺默认离线缓存失败；给那5项提供显式本地权重的隔离fixture后全部通过，未修改上游源码。没有把它表述为完整训练/原生/ASR测试套件通过。

## 配套和授权范围

Needle SDK、needle-environments及两个HF资源带Apache-2.0许可。Cactus主仓是另一个带资格/规模条件的许可，不能套用Needle的Apache许可；cq-convert与depth-over-specialization当前快照未找到明确LICENSE，不将其视为可任意商用复用。

Cactus包含旧版Needle结构与通用移动推理代码；它不等于已核实的Needle3 `.cact`运行时源码。cq-convert实际是Gemma相关TurboQuant-H固定量化研究；depth-over-specialization实际是多模态对比编码器实验。名称相近、同组织或README提及不构成兼容证明。
