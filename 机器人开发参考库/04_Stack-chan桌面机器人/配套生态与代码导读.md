## 从输入到机器人行为

MOD 和对话服务 → StackchanContext → 音频、脸和双轴头部；也有 Arduino AI 固件路线与 USB 外部计算路线。

## 配套关系与实现判断

Stack-chan 至少有三条配套路线，应先选路线再选硬件。当前主仓 develop 使用 Moddable 宿主和 JavaScript/TypeScript MOD，motion、conversation、audio、ui 和 connectivity 是可组合能力；网页积木、表情编辑和模拟工具也在主仓。m5stack-avatar 是 Arduino 生态表情库，并非必须与此宿主同时烧录。

主仓 ChatGPT MOD 示例通过 simple-stt-server 接收电脑麦克风的 VOSK 识别文本，另外依赖 VOICEVOX 语音合成服务。这是一条带外部服务的示范链路；VOSK 模型、VOICEVOX core 与音色资源仍需按运行指南准备，代码下载不等于模型环境齐全。

社区 AI_StackChan2 则是 Arduino/PlatformIO 实现，使用 Google Cloud STT 或 Whisper 与 Web VOICEVOX，相关使用说明单独放在 AI_StackChan2_README。stack-chan-tester 用于 PWM 舵机中位、偏移和引脚检查。它们适合不同的装配与软件路线，不能把所有仓库当作叠加插件烧进同一块板。

原作者 stack-chan-dock 当前含 Android 本地语音和电脑 Codex voice 两种外部应用，通过 contracts/usb-cdc-v2 接机器人。这里 dock 指 USB 连接外部计算环境，不能仅按仓库名理解为充电底座。Android 路线把 ASR、LLM、TTS 放到手机；电脑路线连接 app-server，固件本体仍在外部主仓。

moddable-scservo 提供飞特串行舵机驱动和 ID 设置参考。v0 的 PWM/串行舵机外壳、v1 的 XL330，以及当前 M5StackChan CoreS3 目标不能混用 BOM。主仓 .gitmodules 为空，没有待拉取的有效子模块。

## 后续开发接入建议

首轮固定一个 CoreS3 或 DIY 硬件版本，选择 MOD、Arduino AI 或 USB 三者之一跑通。后续借鉴双轴注视、讲话节奏、表情同步和插件隔离，避免同时承担步态开发。

这些为开发建议，本次没有声称完成硬件复现或跨仓兼容性验证。
