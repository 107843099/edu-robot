# 跨项目开发借鉴

这些项目适合拆成外观、表达、语音、运动和创作工具分别研究。下面为面向我们后续开发的建议，已实现的原项目能力仍以各文件夹的代码导读为准。

[项目总览](<00_%E9%A1%B9%E7%9B%AE%E6%80%BB%E8%A7%88.md>)

## 三种对话与运动接入方式

| 架构 | 当前可参考的实现 | 借鉴价值 | 需要自己验证的边界 |
|---|---|---|---|
| 电脑承担对话 机器人承担动作 | 芝麻 Companion 经 HTTP；Stack-chan USB dock | 快速测试角色、回复与动作，便于换模型和修改提示词 | 主机收音和播音位置、网络失联、对话历史、动作打断 |
| 语音设备直接联网 工具调动作 | 小智、Otto、EMO-Dot、RIG-Omni | 角色可脱离电脑，有统一音频状态和设备工具 | 板卡、音频、资源分区、工具参数、服务端和设备版本 |
| 语音板与运动板分开 | Verdure BuddyRover 的小智 S3R 和 C3 底盘；NodeHexa 的外部扩展思路 | 对话与电机实时控制分别演进，便于更换机器人形态 | 串口应答、状态反馈、命令超时、单一运动输出所有者 |

上述三种不是成本或性能排名。先选希望验证的体验，例如一句话能否让机器人回应并挥手，再选择适合现有硬件的路线。芝麻已提供第一种链路，不需要从零假设其完全没有对话；要把麦克风和喇叭装入机身，则另做设备端音频设计。

## 可以形成共用模块的参考

| 自研模块 | 优先阅读 | 建议带回自己的设计 |
|---|---|---|
| 原创角色与外壳 | EMO-Dot、VerdureLab、Stack-chan、AlbertMicro | 保留统一屏幕和主板安装接口，外壳比例与装饰原创，记录重心和维护口 |
| 表情与身体反馈 | Stack-chan、ElectronBot、芝麻、AlbertMicro | 用同一角色状态组织眼睛、嘴形、头部和动作；讲话动作与听讲动作有明确区别 |
| 有限动作工具 | Otto MCP、芝麻命令白名单、Verdure UART | 统一动作名、参数范围、最长持续时间、停止和完成返回；不让语言模型直接给全套关节角 |
| 动作编排与可视化 | Sesame Studio、Otto Playground、Hexapod Link | 教师先用模板修改，学生能预览关键帧并观察真实差异；记录动作与机械版本 |
| 校准与构型参数 | NodeHexa、RookiDroid、XGO runtime | 把方向、中位、限位、关节名称和机械尺寸保存为每台设备的配置 |
| 角色资源与版本 | 小智 assets-generator、Otto GIF、Jumper 内容包 | 固件与角色资产分开发布，同时核对格式、存储、屏幕与解码能力 |
| 对话后端与客户端 | 小智四套后端、py-xiaozhi、Verdure Assistant | 先用电脑测试协议和语音；模型供应商接入与硬件动作适配分开 |
| 仿真到实机 | AlbertPro、sesame-ml、XGO RL、Jumper | 明确训练模型、导出轨迹、闭环策略和实际控制器的区别；每一层保留参数契约 |

## 建议的研究顺序

1. 按你最新倾向，先以小纸壳机器人作为实体第一版的优先候选，完成纸样、供电、六项模块测试、装配与中位记录。再学习 Stack-chan 的双轴表达、EMO-Dot 的屏幕与壳体、Verdure 的造型接口，为后续监听、思考和讲话状态准备表达方式。
2. 跑通一条已有对话链路。电脑路线可读芝麻 Companion；独立语音设备可读小智与 Otto；移动小车可读 Verdure Rover。完成文字或语音输入、工具调用、动作返回和停止的闭环。
3. 加入学生创作。借鉴 Sesame Studio 的关键帧、Otto 的周期幅度和 Hexapod Link 的运动学预览，明确学生能修改什么，以及修改后怎样复测。
4. 选择一种移动机构。芝麻、曼波、AlbertMicro 和 Otto 的复杂度与机械条件不同，先选一条做校准、供电与重复动作记录，不同时复刻全部整机。
5. 把六足、反馈舵机、双足 RL 与 Jumper 作为进阶专题，先做仿真或单模块实验，再决定整机课程和产品投入。

这是依赖关系上的建议，不承诺开发周期或量产能力。每一步以我们的真实接线、版本、重复试验、成本和试教记录作为推进依据。

## 每次采用参考材料应留下的记录

记录原仓库、完整提交、具体文件、匹配硬件、拟借鉴行为、实际修改和测试结果。原代码、模型、PCB、表情和品牌可能有不同条款，各自保留来源。作者历史材料价作为线索，采购价、打印、装配、测试、备件和返修按我们自己的口径核算。

当前参考库保留原始快照，后续开发宜另建工作目录。先在总览选项目，再按代码导读定位模块，能够避免把整个生态重复开发，也避免误用别的板卡分支。

## 纸壳第一版与对话扩展

小纸壳是双轴头部与简单传感器的桌面角色，现有V0.3未提供音频硬件或对话接口。可以先用它研究“触摸与靠近怎样引起动作和表情”，再借鉴芝麻的电脑对话链或小智音频板；跨项目复用的是分层思路，不是现成引脚或可互刷固件。

已从工具包确认重新安装可能擦除NVS、关闭完整系统串口不发急停，以及固件身份识别存在步骤误判。后续自研应严格校验版本和步骤，把停止、配置保存与限位单独设计，保存每台机构的实测记录。详细依据见[小纸壳逆向分析](<15_%E5%B0%8F%E7%BA%B8%E5%A3%B3%E6%9C%BA%E5%99%A8%E4%BA%BA/%E9%80%86%E5%90%91%E5%88%86%E6%9E%90%E4%B8%8E%E8%87%AA%E7%A0%94%E8%BF%81%E7%A7%BB%E6%96%B9%E6%A1%88.md>)。


## 2026-10-03新增：编程状态与端侧意图

| 参考 | 真实实现位置 | 可迁移到我们项目的部分 | 当前证据边界 |
|---|---|---|---|
| [Tiny Engineer](<16_TinyEngineer桌面编程机器人/README.md>) | 电脑钩子→HTTP→C3动作/眼睛/灯/音效 | 学生任务状态、角色故事、归一化关节、素材MOD | 主机测试通过；无板卡编译或真实动作；abort不等于急停 |
| YOVA/Desk HUD/机械番茄钟 | 同作者独立语音、桌面面板、Arduino奖励 | 打断与预算、教师状态面板、任务完成实体反馈 | 已下载源码；没有验证现成Tiny适配器 |
| [Needle](<17_Needle端侧模型/README.md>) | 主机/移动/边缘引擎解析有限工具 | 工具合同、参数、拒绝和端侧意图实验 | 20次离线样例，中文/否定处理对照；当前模型35.3MB，无C3目标 |

建议保持“输入/ASR→意图解析→应用验证→表现状态→设备执行→回执”。Tiny解释机器人如何表达任务阶段；Needle解释文本怎样转为候选工具；纸壳控制器仍掌握校准和停止。先用明确指令跑通执行层，再增加模型，不让对话和意图模型直接输出未经验证的关节PWM。

两轮Needle试验中，环境事实提示改善了否定的拒绝行为，但中文样例仍未产生有效动作；数量词和数字表达也有差异。模型schema、置信度、原生抑制和应用授权应分别检验。Whistle当前语言不含中文/粤语，不能拿英语ASR覆盖香港课堂需求。worker嵌入ABI问题与Cactus跨代差异详见第17项，不先承诺端侧语义检索已经可用。

## 本地小车和四足资料的补充

| 模块 | 可以借鉴 | 应由自研验证的边界 |
|---|---|---|
| 曼波离线语音与动作 | 语音板串口发送有限动作、站立和表情联动 | 本地无命令超时、阻塞动作、语音输出与case不全匹配、两HEX不一致 |
| 小坦克底盘 | 差速混控、校准、网页操纵、NVS路径保存 | 浏览器执行轨迹、最终输出可93%、需实测失联到停止时间 |
| 作者多版本固件 | 手动/智能接管、C3唤醒与动画取舍 | 固件自有源码、引脚和授权未齐，版本不能任意交换 |
| 本地媒体服务 | 文件索引、查询、歌词、分段流 | 客户端源码缺失，不能只启动服务器就声称已接入机器人 |

纸壳首版保留双轴校准、OLED和触摸的独立执行层。对话/Needle解析后仅产生可验证的有限指令，由设备判断当前控制来源、角度/速度范围和有效期。手动接管、错误和断联先停止，再变更模式。移动底盘作为下一阶段独立模块，不能混用四腿舵机和TB6612电机接口。
