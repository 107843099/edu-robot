## 从输入到机器人行为

ASR Pro 语音命令 → 串口动作编号 → STM32 动作任务和姿势表 → 4 路 PWM 舵机；OLED 和语音合成按模式联动。

## 配套关系与实现判断

Russell 的 STM32 工程、ASRPro_Code 与 ESP32 子工程已经在同一仓库内，不必把“配套”仅理解为另一个 GitHub 地址。主链路是语音命令映射到动作编号，STM32 负责执行；SYN6288 是语音合成模块，不因此产生大模型问答能力。

User 下的新任务层把动作、传感器、音频、安全和性能探针拆开。ActionTask 使用 PoseStep 表指定四个舵机角度与时长；Mode 还保留旧行为分支。借鉴时要同时看 main 的实际调用，而不能只看重构说明就断言所有动作都不阻塞。

你给出的 Herobrine 立创项目另有 ASR Pro、CubeMX 和 Keil 附件、5 舵机硬件与 MakerWorld 外壳。没有足够证据确认两套资料同源；将它们保存在同一曼波资料夹的两个来源条目中，严禁交叉套用引脚、图片或许可证。本次已下载 Russell 的 GitHub 全部跟踪文件，Herobrine 的站外工程附件和模型未纳入 GitHub 快照。页面声明部分动作源码被删减，也单独记录。

## 后续开发接入建议

优先研究动作表、串口命令和角色变量。后续若加自由对话，建议沿用有限动作 ID 的边界，再接小智语音板或电脑网关；这是自研方案，并非这份 STM32 仓库已具备的功能。

这些为开发建议，本次没有声称完成硬件复现或跨仓兼容性验证。
