# 小纸壳机器人逆向分析与自研迁移方案

这份分析回答三个研发问题：现有V0.3包实际怎样工作，哪些参数能从文件确认，第一版过后怎样建立可维护的自研方案。结论是：可以复刻一个传感器驱动的双轴纸壳角色；网页教学工具和校准设计很值得借鉴，但当前材料不足以直接重编作者固件，更不能直接接入对话。

证据分为四层：原指南记载；本次读取的网页与清单；实际二进制数据及部分RISC-V指令；假串口运行的界面逻辑。下文的“确认”限于对应层级。没有模拟ESP32整机，没有执行固件或实机量测，反汇编也不是完整源码恢复。

## 镜像和分区到底是什么

六个应用均是0xE9起始的ESP镜像，每个有5个段、头中芯片ID为5、Flash大小编码为4MB；XOR校验与追加SHA256均一致。24个发布文件的大小、SHA256与release.json全部匹配。这些验证证明文件一致性，不证明发布者身份或运行安全。[Espressif镜像格式](https://docs.espressif.com/projects/esptool/en/latest/esp32c3/advanced-topics/firmware-image-format.html)

| 写入文件 | Flash地址 | 当前包的作用 |
|---|---|---|
| bootloader.bin | 0x0000 | 引导应用 |
| partitions.bin | 0x8000 | 分区布局 |
| boot_app0.bin | 0xE000 | OTA启动数据相关区域 |
| firmware.bin | 0x10000 | 当前教学步骤或完整系统应用 |

从partitions.bin解出：NVS `[0x9000,0xE000)`，otadata `[0xE000,0x10000)`，app0 `[0x10000,0x150000)`，app1 `[0x150000,0x290000)`，spiffs `[0x290000,0x3F0000)`，coredump `[0x3F0000,0x400000)`。有app1和spiffs分区不等于本应用实现OTA或已经保存可替换表情资源，本包没有相应功能证据。

完整应用文件的指令段从文件0x20020映射到0x42000020，因此这里的文件偏移0x201EA对应执行地址0x420001EA。下面给出的偏移都不是“写入到Flash的目标地址”。完整段记录见[镜像校验JSON](<%E9%80%86%E5%90%91%E8%AF%81%E6%8D%AE/%E5%9B%BA%E4%BB%B6%E9%95%9C%E5%83%8F%E4%B8%8E%E6%A0%A1%E9%AA%8C.json>)。

## 默认配置与保存机制

| 项目 | 本次确认的值或行为 | 实际边界 |
|---|---|---|
| 水平中位、最小、最大 | 90°、30°、150° | 软件默认，不能保证纸壳和线束可到达全部范围 |
| 俯仰中位、最小、最大 | 90°、60°、120° | 同上，头部承重须实测 |
| 默认结构 | 文件0x120开始的6个小端整数；0x201EA例程复制28字节 | 结构另含反向标志与对齐；不是设备当前读数 |
| 配置有效性 | 0x2025A例程检验min≤center≤max，范围0–180 | 只检验数值，不检测机械碰撞 |
| NVS命名空间 | `cardboard` | 0xA08字符串与读取路径相互对应 |
| NVS键 | magic、schema、pan_c/min/max、tilt_c/min/max、pan_rev、tilt_rev | 存在键不意味着当前网页能编辑全部键 |
| 配置版本 | magic=0x43424F54，schema=1 | 0x202E8至0x20306中的比较可定位 |
| 默认回中B | 网页称回默认90°，不覆盖自定义中位 | 与保存V、回自定义C是三件不同的事 |

读取和保存指令分别位于0x20294至0x203CE、0x203DE至0x20510，键名为0x330至0x380。边界和中位结构的解释与键读取、数值验证和默认拷贝相互印证，不仅是搜索到字符串。证据：[默认结构](<%E9%80%86%E5%90%91%E8%AF%81%E6%8D%AE/%E6%A0%A1%E5%87%86%E9%BB%98%E8%AE%A4%E6%95%B0%E6%8D%AE.json>)、[关键指令](<%E9%80%86%E5%90%91%E8%AF%81%E6%8D%AE/06-robot_%E5%85%B3%E9%94%AE%E6%8C%87%E4%BB%A4.txt>)。

网页上的`pan=当前/目标`和`tilt=当前/目标`是软件状态。本方案没有接入舵机位置反馈，因此“当前90°”不等于已经测得真实轴在90°。这也是装舵盘、校准与轻载验收必须分开的原因。

## 输入处理与动作为何显得有回应

初始化0x21132附近传GPIO4与低有效参数，0x2113E传GPIO3与低有效参数，0x2114A传GPIO10与高有效参数。0x200B4输入更新函数先记录原始状态变化的时间，稳定超过39毫秒才更新稳定状态，即约40毫秒去抖。下面是按指令解释整理的等价轮廓，不是作者源码：

```text
active = (pin == 配置的有效电平)
if active != 上次原始值:
    上次原始值 = active
    变化时刻 = now
if 上次原始值 != 稳定值 and (now - 变化时刻) > 39ms:
    稳定值 = 上次原始值
```

0x20A52至0x20B86正常状态分支支持：触摸优先引发PET回应；一侧红外有效时进入TRACK并调整水平目标；两侧都有效时不按单侧分支继续推移水平目标；失去目标后可回空闲并转入SEARCH。字符串含BOOT、IDLE、TRACK、SEARCH、PET、ERROR，但仅有名字不能证明状态间所有时间与优先级已经恢复。

可进一步确认的局部：单侧TRACK目标以1°增减，更新条件约20毫秒；这是目标值更新节奏，不能当作真实轴50°/秒的测速。0x2069A附近的触摸动作从俯仰中心到上边界之间选择有限偏移，局部上限15°，不等于所有触摸场景都有固定幅度。未穷尽的搜索时机、表情绘图、OLED故障恢复及随机节奏保留为待验证。

工程解释：两路红外提供简单方向线索，触摸切换到较明显的回应，加上平缓头动和表情，人就容易把它读成一个角色。第一版最该复现的是输入、状态、表情与动作间的可辨认关系；之后再设计自己的角色节奏。

## 舵机PWM的局部还原

0x201A2初始化函数可见50Hz与14位分辨率参数；0x20134写角函数先按反向标志转换`180-angle`，再钳制到0–180，把角度线性映射到500–2500微秒，最后换算为20,000微秒周期的占空比。0x20106停止函数写零并解除输出关联。

这些是程序侧参数，不是对所有SG90实物的脉宽兼容或机械承载保证。自研时应把脉宽、方向、机械限位与上电策略做成可核对的板级配置，先在裸舵机与轻机构上确定自己的范围，不能仅改外壳后沿用全部默认值。

水平教学程序的0x3E4数据是90、85、95、90，0x1036A附近有超过2000毫秒的保活判断及停止分支。网页的2200毫秒失联判定属于另一层。不能把教学固件的停止条件外推为完整系统必然随网页失联停止。

## 浏览器与固件之间的协议

串口115200，UTF-8文本按换行分隔，写入使用Promise队列保证顺序。USB候选筛选303A:1001，随后还要识别固件；CH340/CP210x不在本包筛选范围。

| 命令 | 网页或固件可见含义 | 验证层级 |
|---|---|---|
| `?` | 查询身份与状态 | 网页发送，固件字符串对应 |
| `PING` | 教学连接保活 | 网页500ms发送，教学二进制有超时分支 |
| `START servo_pan/servo_tilt`、`STOP` | 启动一轮教学动作、停止 | 网页要求身份与OLED有效 |
| `1`、`2` | 正常运行、校准 | 网页控件与协议 |
| `B`、`C` | 默认90°、自定义中位 | B需caps=default_center能力标记 |
| `A/D`、`W/S` | 水平左/右、俯仰上/下，每次1° | 网页与固件帮助文本；实物方向待验 |
| `V` | 保存中位 | 网页控件、NVS保存路径 |
| `X`、`R` | PWM急停、恢复驱动而不自动回中 | 网页与局部指令相互支持 |
| `3`、`P/T/L/Z` | 自检、打印/遥测、载入/清除NVS的额外命令线索 | 固件帮助与部分分支可见，默认网页白名单未开放；本次未发送 |

身份应为`CB_TEST id=... version=0.3 oled=...`或`CB_ROBOT version=0.3 ... caps=default_center`。状态可带mode、config、state、stop、servos、pan、tilt、irL、irR、touch。**当前网页只选择性解析这些字段，没有把全部传感器和状态变成实时可见记录。**后续调试可增加原始状态日志，但须在独立开发副本完成。

初次识别等待4秒，每600ms询问；识别后每500ms保活，2200ms没有状态则断开。握手成功、OLED回答、观察动作正常是三种不同证据。

## 三个工具问题及复现证据

| 问题 | 可复核证据 | 对第一版的影响 |
|---|---|---|
| README说默认不整片擦除，代码却先擦除 | 六manifest关闭Improv等待；无Improv普通安装进入`_startInstall(true)`；随后先`eraseFlash()`再`writeFlash({eraseAll:false})` | 不承诺保留NVS；安装前记录，重刷后校准 |
| 非完整系统步骤接受CB_ROBOT | 假串口在display步骤注入同版本CB_ROBOT，matched变true但robot仍false | “固件匹配”可能不代表本步骤固件；核对具体身份与实物画面 |
| 关闭完整系统串口不停止 | `disconnect()`仅对`!s.robot`发STOP；模拟robot断开发送列表为空 | 页面后台、关闭或串口释放均不能作为完整系统急停 |

第三点还影响文案：页面`visibilitychange`调用断开并显示“测试已停止”，但完整系统没有对应停止发送。校准状态下是否仍持力、自主动作是否继续应分别观察，不能把提示当作动作确认。

证据为[安装器控制流摘录](<%E9%80%86%E5%90%91%E8%AF%81%E6%8D%AE/%E5%AE%89%E8%A3%85%E5%99%A8%E6%93%A6%E9%99%A4%E8%B7%AF%E5%BE%84%E6%91%98%E5%BD%95.json>)及[7项模拟结果](<%E9%80%86%E5%90%91%E8%AF%81%E6%8D%AE/%E4%B8%B2%E5%8F%A3%E6%A8%A1%E6%8B%9F%E6%A0%B8%E6%9F%A5%E7%BB%93%E6%9E%9C.json>)。模拟只执行从原文件抽取的TestConnection类，端口、writer和事件均替换为假对象；不启动网页安装器，不访问USB。

页面里的OLED图和验收卡片来自静态模板，不是机器人屏幕实时回传；“下一步”和人工确认也不是自动硬件检测。后续教学版需要保存每项的实际观察与错误，而不是只有流程进度。

## 自研迁移怎么分步做

以下是研发建议，尚未实现，也没有生成新固件。

| 阶段 | 建议成果 | 过关条件 |
|---|---|---|
| 第一版复刻 | 固定原V0.3、纸样、电源与校准，留下单台验收记录 | 六项实物观察、重启中位、线束和机械干涉检查 |
| 可维护固件 | 获取可重编工程或根据理解独立实现；板级引脚、输入处理、行为、表情、动作、配置分模块 | 自己能构建并解释一套固件，能观测输入与输出状态 |
| 稳定工具 | 严格核对步骤和版本；统一急停策略；明确重刷是否保留参数；导出记录 | 错固件被拒绝、断开语义明确、保存/重启/重刷分开验收 |
| 原创角色 | 角色表情与动作作为资源，外壳模板可替换，连接接口固定 | 换纸壳后仍可校准、维修和复测 |
| 对话扩展 | 电脑或音频板承担ASR/模型/TTS，动作板负责有限动作与范围检查 | 说话/倾听状态可区分，命令有完成与停止回报 |

建议的动作抽象是“看左、看右、点头、摸头回应、回中、停止”等有限动作，传感器和对话都调用同一个动作入口。它们**不是当前V0.3已实现的网络API**。当前串口只提供现有控制与校准命令，不能把模型输出的任意角度直接传入现成包。

先用[芝麻电脑对话链](<../01_%E8%8A%9D%E9%BA%BB%E6%9C%BA%E5%99%A8%E4%BA%BA/%E9%85%8D%E5%A5%97%E7%94%9F%E6%80%81%E4%B8%8E%E4%BB%A3%E7%A0%81%E5%AF%BC%E8%AF%BB.md>)研究ASR、模型与TTS，再用[小智语音生态](<../08_%E5%B0%8F%E6%99%BA%E8%AF%AD%E9%9F%B3%E6%9C%BA%E5%99%A8%E4%BA%BA/%E9%85%8D%E5%A5%97%E7%94%9F%E6%80%81%E4%B8%8E%E4%BB%A3%E7%A0%81%E5%AF%BC%E8%AF%BB.md>)研究独立音频板。C3现有7根功能信号及启动、USB资源约束需要重新审查；“焊上麦克风和喇叭即可聊天”目前没有证据。

## 哪些信息仍不能从逆向保证

完整源代码、作者构建版本、所有异常分支、真实SG90脉宽与承载、实际角度、纸板寿命、多人操作可靠性、全部表情素材与许可，均未被本次核查证明。现有证据足以制定首台复刻顺序与自研边界，不能替代实物验收或声称恢复了作者完整源码。
