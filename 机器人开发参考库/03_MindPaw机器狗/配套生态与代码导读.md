## 从输入到机器人行为

ESP8266 网页和传感输入 → 情绪及动作模块 → 舵机与 OLED；AI 网关和重建服务放在外部电脑或服务器。

## 配套关系与实现判断

MindPaw 的基础固件、网页控制、PCB/STL 和 AI 基础设施都在一个仓库中。MindPaw_main 是设备工程，ai-infra/gateway 是外部网关，ai-infra/recon 是图像重建服务；后两者不能当作 ESP8266 芯片内运行的模型。

设备侧 emotion_engine、motion_emotion、multimodal_fusion 和 doubao_agent 展示输入、行为状态和动作的分工。建议沿调用方向读到实际网络请求与运动输出，区分可直接使用的驱动与还需要服务端配置的扩展。

gesture_nn 明示权重为占位且未经训练。重建 README 与 mock_recon 表明默认模拟输出，weights 目录没有随仓库附带模型。上游 ABot-Recon 是算法参考，不构成已完成的机身视觉能力。引脚说明存在 GPIO16 和 SPI 的资源冲突，摄像头文档与源码型号也需统一。

因此可以借鉴模型网关、结构化响应和角色变量，但本次不把“手势识别、3D 重建、低延迟数字”列为实测能力。软件 MIT、硬件/STL 非商业许可、文档 CC BY 的边界分别列在详细资料中。

## 后续开发接入建议

先验证基础舵机、表情和网页；AI 网关先用模拟响应测试格式。把占位模型、引脚冲突和缺少权重列入补齐清单后，再决定是否投入真实视觉实现。

这些为开发建议，本次没有声称完成硬件复现或跨仓兼容性验证。
