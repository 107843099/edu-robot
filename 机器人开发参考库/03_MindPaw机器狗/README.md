## 已核对的硬件与能力

基础为 ESP8266／ESP12F、4 舵机与 OLED；仓库有 Arduino／PlatformIO 工程、网页、PCB 工程及 STL。手势模型源码标明权重未训练，三维重建模块默认使用 mock，未附预训练权重。

对话和控制配套现状：同仓库含模型网关；手势权重与重建部分仍有占位实现。

ESP8266 网页和传感输入 → 情绪及动作模块 → 舵机与 OLED；AI 网关和重建服务放在外部电脑或服务器。

## 外观代码与产品思路借鉴

以下为面向后续自研与课程的分析建议。

- 软件：研究情绪变量、动作表情映射和多输入处理怎样分层，以便在自研程序中保留清晰的输入与输出。
- 系统：将可选云端能力放入网关，基础动作留在设备端，便于控制网络依赖与故障范围。
- 界面：网页动作面板与配置页可作为教师调试工具的参考；模型输出先作结构与参数检查。

## 开发试验建议

只选一个输入、一个动作和一组表情形成最小闭环；逐项核对引脚与真实器件，再决定是否保留进阶模型模块。

先验证基础舵机、表情和网页；AI 网关先用模拟响应测试格式。把占位模型、引脚冲突和缺少权重列入补齐清单后，再决定是否投入真实视觉实现。
