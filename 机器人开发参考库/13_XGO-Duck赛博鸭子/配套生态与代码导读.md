## 从输入到机器人行为

训练电脑的 MuJoCo 与 PPO → ONNX → UNO Q Linux 策略与网页 → Arduino Bridge → STM32 舵机及 IMU；嘴部另控制。

## 配套关系与实现判断

XGO-Duck 应从硬件、runtime、RL 三仓同时看。硬件含15个飞特1910舵机、UNO Q、扩展板、IMU、STL与25页装配指南；策略输出14个关节，嘴部舵机单独控制。训练时的关节顺序和设备总线顺序不能混成同一数组。

Runtime 把 Linux 的50Hz ONNX 推理与 STM32 的100Hz 总线环分开，Bridge 传状态和目标，网页做 ID 设置、校准和模式切换。已有 walk、getup、pick、roulade 四个模型；每个输入61维、动作14维。端口9527、校准零位文件、命令心跳和失联禁用都可从当前 README 与代码核对，作者写的频率不等于本次实测。

RL 仓给出仿真任务、导出与 BAM 执行器建模参考，模型格式和尺度需跟 runtime 一起固定。Pollen Microduck 和 microduck_rl 是上游，本次也已下载；当前上游运行时使用 RK3566 与 Rust 服务体系，与 UNO Q 改编不是同一硬件或直接替换。上游模型许可有非商业范围，不能从软件 Apache 推断全部模型商用。

同组织 RIG-Omni 是独立的 ESP32-S3 多形态语音固件，支持 Puppy、Hover、Arm、Tars，共享音频、网络与 MCP，板级实现各自运动。它很适合借鉴多造型平台思路，但不是这只鸭子的现成对话插件。

硬件仓 LICENSING.md 表明最终正式许可未附；runtime 也未找到根 LICENSE，RL 的 Apache 分别记录。软硬件下载齐并不解决这些授权范围。

## 后续开发接入建议

优先研究关节映射、执行器模型和仿真到实机的契约。整机复现先逐个设 ID、固定零位、支撑下测回传，再验证默认姿态；若以后加对话，采用独立高层指令接口，不让语言模型输出每周期关节角。

这些为开发建议，本次没有声称完成硬件复现或跨仓兼容性验证。
