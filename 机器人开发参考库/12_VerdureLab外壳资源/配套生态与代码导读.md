## 从输入到机器人行为

VerdureLab 提供造型；VerdiBot 通过 Assistant API 对话；BuddyRover 用小智语音板经 UART 指挥 C3 底盘。

## 配套关系与实现判断

VerdureLab 是多个外壳的集合，不是一套通用机器人固件。STL、Fusion 源文件和具体模型 README 要按目录读。verdure-buddy-rover、verdure-emo、verdure-duck、pendant 等用途不同，不能只选一个壳就认为能直接运行。

VerdiBot 是树莓派桌面机器人，Verdure.Assistant.Api 提供语音和音乐 HTTP API，PiWiFiAP 处理树莓派配网。Assistant 当前使用 .NET10，有 Core、Console、API、WinUI、MAUI 等分层；xiaozhi-sharp 是关联的小智客户端参考。它们适合学习外部服务与硬件控制分离，不能把所有桌面 UI 的功能当作树莓派已验证特性。

BuddyRover 是另一条两板路线：M5Stack Atom Echo S3R 运行 maker-community/xiaozhi-esp32 的 verdure-buddy-rover 分支，C3 SuperMini 固件运行电机、BQ27220 电池计量、BLE 按键和 RGB。设备端 MCP 转成 forward、back、turn、stop 等 UART 行命令，再读取 OK 或 ERR；异步 EVT 和 battery 不应误作应答。

实际语音板源码除了 self.chassis.* 和 self.led.*，还注册 self.rover.action、light 和 get_status。整合时以当前源码为准；速度参数和限制也要核对实际 firmware，不能只复制文档里的一张映射表。通用资料已提供幂等 stop、请求应答和输入缓冲分离的思路。

taishanpi 的 .NET IoT 小仓含 SPI 显示、I2C 舵机和 USB 音频上手记录，属于同组织的替代计算板研究，不是已经完整移植的 VerdiBot 成品。Rover 的语音分支本次已下载，避免误用小智仓默认分支。

## 后续开发接入建议

桌面版可先评估 VerdiBot 加 Assistant；移动版选 Rover 两板链路。统一行为接口与角色资产，再在原创外壳上调整显示、线束、散热与维护口。

这些为开发建议，本次没有声称完成硬件复现或跨仓兼容性验证。
