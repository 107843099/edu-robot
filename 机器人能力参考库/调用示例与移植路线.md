# 调用示例与移植路线

以下是**接入片段**，需要放进对应原工程或已初始化的同类开发工程。它们不构成统一机器人SDK；示例未烧录或驱动实体机器人。每段链接到能力卡，卡片记录准确源码与固定版本。

## 1. OLED自动眨眼：RoboEyes

适用：Arduino、Adafruit_GFX兼容驱动；先选择实际SSD1306或SH1106。以下为SSD1306例子，I2C引脚、地址和屏幕尺寸由你的板型确定。

```cpp
#include <Adafruit_GFX.h>
#include <Adafruit_SSD1306.h>
#include <FluxGarage_RoboEyes.h>

Adafruit_SSD1306 display(128, 64, &Wire, -1);
RoboEyes<Adafruit_SSD1306> eyes(display);

// 在Wire和display.begin(...)已成功之后调用：
void configureFace() {
  eyes.begin(128, 64, 30);
  eyes.setMood(HAPPY);
  eyes.setAutoblinker(ON, 3, 2); // 秒
  eyes.setIdleMode(ON, 2, 2);   // 秒
}
// 主循环持续调用 eyes.update();
// 一次眨眼：eyes.blink(); 看向右侧：eyes.setPosition(E);
```

提取范围：`通用库源码/FluxGarage__RoboEyes/`及显示驱动，保留GPL许可。它拥有眼睛渲染与屏幕刷新；同一时刻不要让另一表情播放器反复清屏。见[E01](<01_表情显示/E01_RoboEyes%20参数化眼睛、眨眼与注视.md>)、[A01](<05_媒体与资源/A01_GFX%20位图格式与显示驱动选择.md>)。

## 2. 16种成品表情：TinyEngineer独立组件

适用：纯C++组件＋自己的显示驱动。完整提取`16_TinyEngineer…/仓库/jamro__tiny-engineer/lib/TinyEngineerExpressions/`，包含`.cpp`和资产头文件。

```cpp
#include <TinyEngineerExpressions.h>
namespace te = tiny_engineer::expressions;
uint8_t faceFrame[te::kFrameBytes]; // 512字节

// selectedAtMs在切换表情时更新；display已初始化为128×64。
void drawHappy(uint32_t nowMs, uint32_t selectedAtMs) {
  if (!te::render(te::Expression::Happy,
                  nowMs - selectedAtMs, faceFrame, sizeof(faceFrame))) return;
  display.clearDisplay();
  display.drawBitmap(0, 16, faceFrame, te::kWidth, te::kHeight, 1);
  display.display();
}
```

每种30帧、100ms/帧，128×32在128×64屏上居中。定时刷新由外部负责，不同时启用RoboEyes；可通过显式renderer选择切换两条路线。见[E02](<01_表情显示/E02_TinyEngineer%20独立%2016%20种位图表情.md>)。

## 3. 两舵机底层：ESP32Servo

适用：Arduino-ESP32；`PAN_PIN`、`MIN_US`、`MAX_US`必须来自已确认的目标接线与舵机校准。

```cpp
#include <ESP32Servo.h>
Servo pan;
// setup里的接入片段：
// pan.setPeriodHertz(50);
// pan.attach(PAN_PIN, MIN_US, MAX_US);
// pan.write(calibratedCenterDeg);
// 停止该通道PWM：pan.detach();
```

此库只管输出，不生成“点头”。新动作控制器保存起点、目标、开始时间和持续时间，在loop按时间插值，再调用`write`。中心、反向、软件限位应逐关节记录；借芝麻的函数时不要照抄732–2929µs。见[M01](<02_动作与运动/M01_ESP32Servo%20舵机角度与脉宽驱动.md>)、[M20](<02_动作与运动/M20_TinyEngineer%20舵机平滑、限位与释放输出.md>)。

## 4. 多舵机底层：PCA9685

适用：Arduino＋PCA9685；这是微秒接口，不是degree或tick接口。

```cpp
#include <Adafruit_PWMServoDriver.h>
Adafruit_PWMServoDriver pwm(0x40); // 按实际地址修改
// Wire初始化后：
// pwm.begin();
// pwm.setPWMFreq(50);
// pwm.writeMicroseconds(channel, calibratedPulseUs);
```

角度→微秒是另一层映射。若使用`setPWM(channel,on,off)`，参数为12bit周期计数；full-on/full-off不能互换。Tiny的释放函数包含状态/OE配套，不能只复制一行。见[M02](<02_动作与运动/M02_PCA9685%20多通道舵机输出.md>)。

## 6. 芝麻远程表情与挥手

适用：匹配芝麻HTTP固件。设备地址需替换；示例只是文档，没有发往真实设备。

```sh
curl -X POST 'http://DEVICE_IP/api/command' \
  -H 'Content-Type: application/json' --data '{"face":"happy"}'
curl -X POST 'http://DEVICE_IP/api/command' \
  -H 'Content-Type: application/json' --data '{"command":"wave"}'
```

`runWavePose`是固件函数名，`wave`才是此远程命令。说话显示`talk_happy`是预绘帧，主机配套控制启停；不等同音量嘴形。见[C01](<04_通信与工具调用/C01_芝麻%20HTTP%20动作与表情接口.md>)、[C02](<04_通信与工具调用/C02_芝麻同作者语音、LLM%20与机器人桥接.md>)。

## 7. 曼波非阻塞动作任务

适用：GitHub的STM32 ActionTask工程，先完成舵机初始化。

```c
#include "ActionTask.h"
// 初始化阶段：ActionTask_Init();
// 请求时：uint8_t accepted = ActionTask_RequestMotion(ACTION_HELLO);
// 每次主循环：ActionTask_Run(now_ms);
// 取消并回90度：ActionTask_AbortToSafeStop();
```

`RequestMotion`只有ActionId参数；`Run`才接收毫秒时间。本地旧包的`mode_hello`是另一套阻塞实现。见[M04](<02_动作与运动/M04_曼波%20GitHub%20非阻塞%20ActionTask.md>)、[M05](<02_动作与运动/M05_曼波本地阻塞动作及语音映射.md>)。

## 8. MindPaw情感动作

适用：原四舵机Arduino工程，Servo对象已attach。

```cpp
MotionEmotion motion;
// motion.attach(s1, s2, s3, s4);
// motion.setEmotionalIntensity(0.0f, 0.5f);
// motion.trigger(ACTION_NOD, 1);
// loop里：motion.loop();
// 停播放：motion.stop(); // 不回中，不关闭PWM
```

若设置`OscillatorParams`，center/amplitude是度、frequency是Hz、phase是弧度、durationMs是毫秒。纸壳两舵机需改通道与预设，并保持同一舵机单一写入者。见[M06](<02_动作与运动/M06_MindPaw%20正弦情感动作与离散动作.md>)。

## 9. Stack-chan Mod注视

适用：当前Moddable固件的Mod生命周期，坐标单位米。

```js
export function onContextCreated(robot) {
  robot.motion.lookAt([0.5, 0.0, 0.0]);

```

姿态角是弧度；需按驱动、坐标轴和头部几何实现。不要把此JS放进Arduino `.ino`。周期动作还要遵守上下文关闭/Timer清理。见[M08](<02_动作与运动/M08_Stack-chan%20注视、避视与头部姿态.md>)。

## 11. Needle只生成工具提案

适用：已配置对应ABI、generation和本地权重的Needle Python环境。下例新定义schema，没有实现实体机器人适配器，也不会调用电机。

```python
from needle import Needle

tools = [{
    "name": "set_expression",
    "description": "Select an existing robot face preset.",
    "parameters": {
        "type": "object",
        "properties": {"name": {"type": "string", "enum": ["happy", "sad"]}},
        "required": ["name"],
        "additionalProperties": False,
    },
}]
agent = Needle(tools=tools, weights=LOCAL_WEIGHT_PATH, stateless=True)
try:
    proposal = agent.complete("Show a happy face.")
finally:
    agent.close()
# 接下来由自己的dispatcher验证proposal并映射到C01或另一真实固件接口。
```

`LOCAL_WEIGHT_PATH`需定义。`complete`只提案；`run`会执行已注册Python函数。固件动作、ACK、范围和忙状态不会由schema自动实现。见[C04](<04_通信与工具调用/C04_Needle%20端侧工具提案与%20schema.md>)、[C05](<04_通信与工具调用/C05_Needle%20run%20自动执行与%20complete%20的区别.md>)。

## 12. Otto MCP动作参数

适用：归档Otto分支已经注册的工具；以下是工具调用内容，不是另发一个HTTP到未知端点。

```json
{"name":"self.otto.action","arguments":{"action":"hand_wave","steps":1,"speed":1000,"amount":30,"arm_swing":30,"dir":1}}
```

`speed`是周期毫秒，小值更快；回中用`action:"home"`。不要使用未注册的`self.otto.home`。高级servo_sequences需要另外读取完整格式与限幅。见[C06](<04_通信与工具调用/C06_小智%20Otto%20MCP%2022动作与校准工具.md>)。

## 13. Rover串口双轮驱动

适用：原ESP32-C3电机板。每行换行终止，需解析OK/ERR与异步EVT。

```text
ping
status
drive 30 30
stop
```

`drive`两轮为百分比；`motor`底层PWM采用±255。语音主板需匹配Atom Echo S3R分支，不能直接把MCP JSON发给电机板。见[C07](<04_通信与工具调用/C07_Rover%20UART%20命令、ACK%20与异步状态.md>)。

## 14. 坦克WebSocket控制

适用：已连接原网页配置的`ws://…/ws`或`wss://…/ws`，下面仅是消息内容。

```json
{"left":30,"right":30}
```

停止消息：`{"stop":true}`；速度消息为`{"speed":70}`。必须持续心跳/控制并处理默认500ms超时；路径仍由浏览器回放。处理器是字符串搜索解析，不把混合字段当可靠通用JSON协议；新工程建议明确消息类型与正规解析器。见[C08](<04_通信与工具调用/C08_坦克%20WebSocket、路径回放与超时停车.md>)。

## 纸壳第一版的复用顺序

1. **先沿原指南验收结构与模块**：确认主控、OLED、pan/tilt、供电、中心和停止方式。用I06保留模块验收；BIN的内部表情源码未提供，不能承诺直接修改。
2. **自建可维护表情工程时选一条渲染路线**：RoboEyes参数绘制适合轻量眨眼/注视；Tiny独立组件适合成品情绪帧。先OLED单独运行，再接舵机。
3. **接两舵机非阻塞动作**：借M04的deadline结构或M20的目标/速度/update；重新标定pan/tilt。MindPaw正弦动作需缩减为两通道。停止单独立即处理，和回中/释放分开。
4. **再接电脑或小智对话**：电脑可借芝麻语音桥替换传输；小智需要匹配板型、音频、资源和IDF。speaking/listening只驱动有限表情与动作，不让LLM任意写角度。
5. **最后引入Needle提案**：电脑/移动端运行，选择已经实现的有限工具；先验证提案，再调用已有串口/HTTP入口。尚未实现的适配器单独立项，不写成“现成可用”。

新项目每个能力应记录：来源提交、提取文件、库版本、板型、通道/引脚、单位、预设名、调用/停止/完成接口与验证结果。这样Codex可以继续复用同一组件，避免重复开发。
